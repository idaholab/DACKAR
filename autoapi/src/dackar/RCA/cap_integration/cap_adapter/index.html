"submitted" — accepted by CMMS synchronously. "pending" — written to drop zone; CMMS import job pending. "partial" — some records submitted, some failed. "failed" — no records submitted. "noop" — NoOpCAPAdapter; nothing was done.

Bases: Protocol

Protocol for CAP submission adapters.

All implementations must be idempotent with respect to package["export_id"]: submitting the same package twice must not create duplicate CMMS records.

class src.dackar.RCA.cap_integration.cap_adapter.FileDropCAPAdapter(drop_dir)[source]¶

Writes the CAPExportPackage as a JSON file to a watched directory.

This is the default adapter for dev and pre-live deployments. The plant’s CMMS import job polls the directory and ingests the file asynchronously. Returns a receipt with status="pending" and an empty cr_numbers list — CMMS record numbers are not available at submission time.

Parameters:

drop_dir (str | pathlib.Path) – Directory where export files are written. Created if absent.

drop_dir[source]¶
submit(package)[source]¶

Write the package to the drop zone as JSON and return a receipt.

The file is written atomically (to a hidden *.tmp sibling, then os.replace``d into place) so a CMMS import job polling the directory never observes a partially written ``cap_export_*.json file.

Parameters:

package (JsonDict) – Dict conforming to schemas/cap_export_package.json.

Returns:

Silently discards the package. Used in unit tests and CI.

Returns a receipt with status="noop" and an empty cr_numbers list. Makes no file I/O and has no external dependencies.
