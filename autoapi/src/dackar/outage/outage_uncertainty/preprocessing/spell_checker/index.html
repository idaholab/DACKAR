src.dackar.outage.outage_uncertainty.preprocessing.spell_checker¶

Domain-aware spell checker for nuclear outage activity descriptions.

Design rationale¶

Generic spell checkers (pyspellchecker, autocorrect, etc.) are inappropriate here for two reasons:

  1. Domain vocabulary — nuclear outage terms such as "pressurizer", "impeller", "torquing" are not in standard English dictionaries and would be “corrected” to unrelated words.

  2. Abbreviated tokens — abbreviations that were not fully expanded (or are new to the dictionary) must pass through unchanged; a generic checker would mangle them.

This checker builds its vocabulary from the package’s own domain data (nuclear abbreviation expansions, taxonomy keywords, and a static engineering word list) so it can only suggest corrections to words that belong to the nuclear outage domain.

Algorithm¶

For each token in the cleaned text:

  1. Pass-through if the token is shorter than min_token_len (default 5) or is already in the domain vocabulary.

  2. Otherwise call difflib.get_close_matches() against the vocabulary with a configurable cutoff (default 0.85). This is equivalent to accepting corrections whose SequenceMatcher ratio ≥ cutoff.

  3. If a match is found, substitute — unless the match is simply the token with a prefix or suffix removed (a strict substring ≥ 2 characters shorter). Those are rejected because for prefixed domain verbs the nearest vocabulary word is the opposite operation (uninstall → install, unisolate → isolate, reenergize → energize, retorque → torque), not a typo correction. Otherwise leave the original token.

The 0.85 threshold was validated on a representative set of P6 typos:

  • calibartion → calibration (ratio 0.91)

  • presure → pressure (ratio 0.93)

  • transmiter → transmitter (ratio 0.95)

  • maintenace → maintenance (ratio 0.95)

  • inspcetion → inspection (ratio 0.90)

and against common false-positive pairs (primary / primate ratio 0.71; install / instill ratio 0.86 which is borderline — resolved by install matching itself exactly at 1.0). Affix variants that clear the ratio cutoff but invert meaning are handled by the substring guard in step 3 rather than by the ratio alone.

No external dependencies are required. The checker is deterministic and fast enough for the corpus sizes (tens of thousands of activities) encountered in a single-outage planning cycle.

Implementation¶

The closed-vocabulary correction algorithm is the generic dackar.text_processing.VocabSpellChecker.VocabSpellChecker. This module is the outage adapter: it supplies the nuclear-domain vocabulary and keeps the .transform interface expected by ActivityCleaner.

Build the nuclear outage vocabulary from four sources:

  1. Individual words from all nuclear abbreviation expansions (e.g. “main coolant pump” contributes “main”, “coolant”, “pump”).

  2. All keywords from the taxonomy rules (single-word and phrase parts).

  3. The static _COMMON_ENGINEERING_WORDS set.

  4. Any extra_vocab supplied by the caller.

Bases: dackar.text_processing.VocabSpellChecker.VocabSpellChecker

Correct residual misspellings using a nuclear outage domain vocabulary.

A thin outage adapter over dackar.text_processing.VocabSpellChecker.VocabSpellChecker: it assembles the nuclear-domain vocabulary and leaves the correction algorithm (.transform) to the base class. The checker only ever substitutes a token with a word drawn from that vocabulary; unknown tokens with no close match are left unchanged.

Parameters:

  • cutoff (float) – Minimum SequenceMatcher ratio for a correction to be accepted. Default 0.85. Lower values increase recall but also increase the risk of false corrections.

  • min_token_len (int) – Tokens shorter than this are never corrected (too short to disambiguate reliably). Default 5.

  • extra_vocab (set[str] | None) – Additional domain words to add to the built-in vocabulary. Useful for plant-specific terminology.
