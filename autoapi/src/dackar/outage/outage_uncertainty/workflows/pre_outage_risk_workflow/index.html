src.dackar.outage.outage_uncertainty.workflows.pre_outage_risk_workflow¶

Pre-outage risk prediction workflow (proactive, multi-component).

Orchestrates Stages D → G of the pre-outage risk pipeline:

D Temporal trend analysis — per-component degradation / overrun trends E Causal chain scoring — emergent-work likelihood formula F Historical float analysis — empirical CP float consumption from training data G Risk register + tier synthesis

This workflow is data-source agnostic: it accepts component_histories and schedule_by_id dicts that may come from a live Neo4j KG query or from a demo fixture. Stages A–C (data ingestion, NLP, KG construction/query) are the caller’s responsibility.

Contrast with the single-activity unexpected-activity workflow in demos/demo_scenarios.py, which handles reactive triage of one activity at a time. This workflow processes all components for a given outage window in batch.

Usage¶

from dackar.outage.outage_uncertainty.services.trend_analysis_service import TrendAnalysisService
from dackar.outage.outage_uncertainty.services.causal_scoring_service import CausalScoringService
from dackar.outage.outage_uncertainty.schedule_risk.historical_float_analyzer import HistoricalFloatAnalyzer
from dackar.outage.outage_uncertainty.services.risk_tier_service import RiskTierService
from dackar.outage.outage_uncertainty.workflows.pre_outage_risk_workflow import PreOutageRiskWorkflow

workflow = PreOutageRiskWorkflow(
    trend_service=TrendAnalysisService(),
    causal_service=CausalScoringService(),
    float_analyzer=HistoricalFloatAnalyzer(),
    tier_service=RiskTierService(sme_override_ids={"1RHS-E-001A"}),
)

result = workflow.run(
    component_histories=component_histories,   # from KG or demo fixture
    schedule_by_id=schedule_by_id,
    components_meta=components_by_id,          # {component_id: {description, ...}}
    training_outages=["RF-20", "RF-21"],
    cycle_order=["RF-20 prep", "RF-21 prep", "RF-22 prep"],
)

Output shape¶

{
    "risk_register":      [...],   # ranked list of all components
    "recommendations":    {...},   # flagged components only
    "flagged_components": [...],
    "true_negatives":     [...],
    "tier_summary":       {...},
    "stage_d":            {...},   # trend profiles
    "stage_e":            {...},   # causal scores
    "stage_f":            {...},   # float impact
}

Execute Stages D–G and return the full result dict.

Parameters:

  • component_histories (Dict[str, JsonDict]) – {component_id: {crs_by_cycle, wos_by_cycle, activities_by_outage, ...}} from a KG query or demo fixture.

  • schedule_by_id (Dict[str, JsonDict]) – {activity_id: schedule_record} with float_consumed_hrs.

  • components_meta (Dict[str, JsonDict]) – {component_id: {description, regulatory_constraint_flag, notes, ...}} for building recommendation cards.

  • training_outages (List[str]) – Ordered list of training outage IDs, e.g. ["RF-20", "RF-21"].

  • cycle_order (List[str]) – Ordered list of all pre-outage cycle names, e.g. ["RF-20 prep", "RF-21 prep", "RF-22 prep"].

Returns:

  • Result dict with keys stage_d, stage_e, stage_f,

  • risk_register, recommendations, flagged_components,
